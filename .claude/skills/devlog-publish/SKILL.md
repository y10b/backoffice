# devlog-publish — 개발 로그 검토·발행

깃액션(`devlog.yml`)이 커밋을 모으고(21:00 KST) 초안을 만든다(22:30). 원래는 사람이 백오피스
`/devlog` 에서 **발행 승인**을 누르고 다음 아침 07:00 에 올라갔다. 이 스킬이 그 승인을 맡고,
승인한 글은 그 자리에서 발행한다.

## 준비

```bash
cd <레포 루트>
test -n "$SUPABASE_URL" && test -n "$SUPABASE_SERVICE_ROLE_KEY" || echo "환경에 Supabase 키 없음 — 중단"
npm ci --omit=dev
R="node --import ./scripts/ts-register.mjs"
```

키가 없으면 아무것도 지어내지 말고 거기서 멈춰 보고한다. GitHub PAT · velog 쿠키 · Gemini 키는
DB 설정 표에서 읽으므로 환경에 따로 필요 없다.

## 1. 초안 읽기

```bash
$R scripts/devlog-review.mjs list
```

초안이 없으면 `$R scripts/devlog.mjs draft` 를 한 번 돌리고 다시 list. 그래도 없으면
("글감 점수가 낮다" 등) 오늘은 끝 — 억지로 만들지 않는다.

## 2. 검토 — 하나라도 걸리면 고치거나 버린다

**버린다** (`drop <id> <사유>`) — 고쳐서 될 일이 아닐 때:
- 회사·고객 코드가 드러난다: `bambitcorporation` 등 차단 소유자 이름, 사내 서비스명, 내부 URL,
  고객사 이름. `from_private: true` 초안은 특히 한 줄씩 본다
- 비밀이 보인다: 토큰·키·비밀번호 형태 문자열, `.env` 값, 개인 이메일·전화번호
- 커밋에 없는 일을 했다고 쓴다 (본문 주장이 source 의 커밋 범위를 벗어남)

**고친다** (`edit <id> <file.md> [새 제목]`) — 고치면 될 때:
- `> TODO` 줄, 빈 섹션, 끊긴 문장
- 확인 안 된 숫자("성능 3배")는 지우거나 커밋에 있는 사실로 바꾼다
- AI 상투어("~에 대해 알아보겠습니다", "결론적으로") 걷어내기
- 제목이 커밋 메시지 나열이면 "무엇을 왜 바꿨나"가 보이게

고칠 때는 새 본문을 스크래치 파일에 써서 넘긴다. 본문 200자 미만이면 발행이 거절된다.

**통과** → `approve <id>`

## 3. 발행

```bash
$R scripts/devlog.mjs publish
```

- `발행 N · 실패 0` 이면 끝
- 실패 사유가 쿠키 만료(`writePost 가 null`, 401)면 **다시 시도하지 않는다.** 글은 승인 상태로
  남아 있으니 사람이 백오피스 설정에서 velog 쿠키를 다시 넣으면 07:00 깃액션이 올린다

## 4. 보고

한두 줄: 발행한 제목과 velog 주소, 버리거나 고친 것과 그 이유. 실패면 무엇이 필요한지.

## 하지 않는 것

- 검토 대기가 아닌 글(published·dropped)은 건드리지 않는다
- 커밋에 없는 내용을 채워 넣지 않는다 — 빈약하면 버린다
- 깃액션 로그·PR·커밋 메시지에 초안 제목이나 비공개 레포 이름을 남기지 않는다
