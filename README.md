# 블로그 백오피스

네이버 **공식 API**로 키워드를 고르고, Gemini 로 초안을 만들어 티스토리에 붙여넣고, 발행 뒤
성과를 다시 회수하는 로컬 백오피스입니다. 방향이 반대인 갈래가 하나 더 있습니다 — 사진에서
출발하는 **네이버 방문 후기**. 깃 커밋에서 출발하는 **개발 로그**(velog)와, 지금은 꺼 둔
**쓰레드**(제휴 게시물 후보)도 있습니다.

네 갈래가 한 저장소에 있지만 서로 독립적입니다. **티스토리만 쓸 거면 자격증명 두 개로 충분합니다.**

| 갈래 | 하는 일 | 필요한 것 |
|---|---|---|
| **티스토리** | 키워드 수집 → 매일 초안 → 복사 | 검색광고 + Gemini |
| **네이버 방문 후기** | 사진 분석 → 카카오 로컬로 상호·주소 보강 → 30초 인터뷰 → 초안 | + 카카오 REST API, OpenAI |
| **개발 로그** | 깃 커밋 수집 → velog 초안 → 승인 → 발행 | + GitHub PAT, velog 쿠키 |
| **쓰레드** | 제휴 게시물 후보 (꺼둠 — 방향이 바뀌어 다시 설계 중) | — |

키워드로 쓰는 글은 안 가본 가게 후기를 지어낼 수 없으니 티스토리뿐입니다 — 네이버는 방문한
곳의 사진·인터뷰가 있어야 쓰는 **네이버 방문 후기**가 맡습니다. `posts.channel` ·
`keyword_pool.channel` 컬럼은 남아 있지만 값은 늘 `tistory` 입니다.

각 화면의 컨트롤 옆 **?** 에 마우스를 올리면 사용법이 나옵니다.

## 실행

```bash
npm install
npm run dev       # http://localhost:3939
```

`.env.local` 에 **저장소 자격증명이 먼저 필요합니다.** 없으면 모든 조회가 안내 문구를
돌려줍니다.

```bash
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

[Supabase](https://supabase.com) 프로젝트를 만들고 `supabase/migrations/` 의 SQL 을 파일명
순서대로 실행하세요. SQL 편집기에 붙여넣어도 되고, 개인 액세스 토큰이 있으면 한 줄로 됩니다.

```bash
SUPABASE_ACCESS_TOKEN=sbp_... SUPABASE_PROJECT_REF=<ref> node scripts/migrate.mjs
```

나머지 API 키는 `.env.local` 이 아니라 **설정 화면**에 넣는 편이 낫습니다 —
DB 에 저장돼 재시작 없이 바꿀 수 있고, 항목마다 `연결 테스트` 버튼이 있습니다.

> 왜 SQLite 가 아닌가: 배포(Vercel)는 파일시스템이 읽기 전용이고 인스턴스마다 초기화됩니다.
> 로컬 파일 DB 에는 쓸 수 없고, 써지더라도 다음 요청은 다른 인스턴스로 갑니다.

## 자격증명

설정 화면 맨 위의 **처음이신가요?** 를 펼치면 같은 표가 나옵니다.

### 필수 — 블로그

**1. 네이버 검색광고 API** · 연관 키워드와 월간 검색수를 가져오는 핵심 소스입니다.
광고를 집행하지 않아도 발급되고 무료입니다.

[searchad.naver.com](https://searchad.naver.com) 로그인 → 우측 상단 **도구 → API 사용 관리**
→ 액세스라이선스와 비밀키 발급. CUSTOMER_ID(숫자)는 같은 화면에 있습니다.

**2. Gemini API** · 블로그 본문·제목·태그를 생성합니다.
[aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에서 발급하세요.

무료 티어는 프로젝트당 요청 수가 정해져 있어 글 몇 개만 써도 429 가 납니다. **키를 여러 개
넣으면 쿼터에 걸린 키를 건너뜁니다** — 설정 화면에 한 줄에 하나씩 넣으세요.

### 선택 — 네이버 방문 후기

**카카오 로컬 API** · 사진에서 읽은 상호명을 정확한 도로명주소·업종으로 보강합니다.
[developers.kakao.com](https://developers.kakao.com) → 내 애플리케이션 → 앱 키의
**REST API 키**(JavaScript 키 아님)를 씁니다.

네이버 지역검색이 같은 자리를 주지만 아래 **현재 발급이 막힌 것**과 같은 `검색` 스코프
소속이라 쓸 수 없어 카카오로 대체했습니다.

**OpenAI API** · 사진 분석(메뉴판 OCR·음식 식별)과 후기 본문 생성을 맡습니다.
[platform.openai.com/api-keys](https://platform.openai.com/api-keys) 에서 발급하고, 설정
화면 **"OpenAI — 네이버 방문 후기"** 카드에 키와 모델(기본 `gpt-5.5`)을 넣으세요. 티스토리
본문은 계속 Gemini 가 맡습니다 — 네이버 방문 후기는 사진(메뉴판 OCR·음식 식별)이 핵심이라
시각 인식이 강한 쪽에, 티스토리는 텍스트 생성 쪽에 맡기도록 채널마다 모델을 나눴습니다.

### 선택 — 개발 로그

| | 무엇에 | 비고 |
|---|---|---|
| **GitHub PAT** | 비공개 레포 포함 커밋 수집 | classic, `repo` 스코프 |
| **velog access_token · refresh_token** | 발행 | 읽기(역동기화)는 토큰 없이 됩니다 |

velog 는 공식 쓰기 API 가 없어 로그인 쿠키로 올립니다. 크롬에서 velog.io 로그인 → F12 →
Application → Cookies → `velog.io` → `access_token` 과 `refresh_token` 값을 둘 다 설정 화면에
붙여넣으세요. access 는 24시간, refresh 는 30일짜리입니다. 둘을 같이 보내면 velog 가 새 토큰을
돌려주고 설정이 자동으로 갱신되므로, 30일 안에 발행이 한 번이라도 있으면 계속 삽니다. 만료되면
발행이 조용히 멈추지 않고 글에 오류로 남으니(아래 개발 로그 절 참고), 그때 다시 꺼내 넣으면
됩니다. 엔드포인트는 v3(`v3.velog.io/graphql`)입니다 — v2 에는 쓰기가 남아 있지 않습니다.

**수집하지 않을 소유자 목록**(기본값 `bambitcorporation`)도 같은 카드에 있습니다 — 회사
레포 코드가 공개 블로그로 새는 걸 막는 마지막 방어선입니다.

### 선택 — 유입 데이터

발행한 글이 실제로 읽히고 돈이 됐는지, 다음에 뭘 써야 하는지 가져옵니다. 네이버 블로그는
외부 스크립트를 막아서 **티스토리에서만 동작합니다.**

인증 방식이 서로 다릅니다.

| | GA4 · 서치콘솔 | 애드센스 |
|---|---|---|
| 방식 | 서비스 계정 JSON (하나로 공용) | OAuth2 사용자 동의 |
| 이유 | 두 API 모두 서비스 계정을 지원 | 구글이 애드센스에는 서비스 계정을 **불허** |

**GA4** — GCP 에서 Analytics Data API 를 켜고 서비스 계정 JSON 키를 발급받아 설정 화면에
붙여넣습니다. 그 다음 **GA4 → 관리 → 속성 액세스 관리**(계정 액세스가 아님)에서 키의
`client_email` 을 **편집자**로 추가하세요. 뷰어가 아니라 편집자인 이유는 조회수만 읽는 게
아니라 `scripts/ga4-setup.mjs` 가 Admin API 로 주요 이벤트(`calculator_use`·`scroll`)와
맞춤 측정기준(`calc_type`)을 멱등하게 설정하기 때문입니다 — 뷰어 권한이면 조회는 되지만
이 설정 호출만 403 이 납니다. 속성 ID 는 측정 ID(`G-XXXXXXX`)가 아니라 **관리 → 속성
설정의 숫자**입니다.

티스토리는 **관리 → 플러그인 → 구글 애널리틱스**에 측정 ID 를 넣으면 끝입니다. 데이터는
소급되지 않으니 빨리 달수록 이득입니다.

**서치콘솔** — 같은 서비스 계정을 그대로 씁니다. [search.google.com/search-console](https://search.google.com/search-console)
에서 티스토리 속성을 등록(URL 접두어 또는 도메인)하고 **설정 → 사용자 및 권한**에서 같은
`client_email` 을 **전체(Full)** 권한으로 추가하세요. GA4 처럼 별도 키를 만들 필요가
없습니다 — 서비스 계정 한 벌이 두 API 를 같이 인증합니다. 같은 화면에서 사이트맵도
제출해 두면 색인이 빨라집니다. 설정 화면에는 서치콘솔 속성 주소만 따로 넣으면 됩니다.

**애드센스** — GCP → 사용자 인증 정보 → **OAuth 클라이언트 ID(웹 애플리케이션)** 를 만들고
승인된 리디렉션 URI 에 아래를 **정확히 그대로** 등록하세요.

```text
http://localhost:3939/api/oauth/callback
```

설정 화면에 클라이언트 ID/시크릿을 저장한 뒤 `애드센스 연결` 을 누르면 동의 후 연결됩니다.
OAuth 동의 화면이 **"테스트" 상태면 refresh token 이 7일마다 만료**되니 프로덕션으로
게시하세요(내부 도구라 심사 없이 전환됩니다).

### 현재 발급이 막힌 것

**네이버 개발자센터의 `검색` 과 `데이터랩`** 은 신규 발급이 안 됩니다. 앱을 등록해도 사용
API 목록에 없고, 호출하면 `401 Scope Status Invalid` 가 옵니다 — 키는 유효한데 앱에 권한이
없다는 뜻입니다.

이 둘은 티스토리 문서수와 검색어 트렌드, 그리고 네이버 방문 후기의 지역검색에 쓰려던
것입니다. 티스토리 쪽은 코드 경로와 UI 열을 그대로 두어, 승인된 키가 생기면 설정 화면에
넣는 것만으로 채워집니다. 없으면 비워두세요 — **광고 흡수율**과 **모바일 비중**이 그
자리를 대신합니다. 네이버 방문 후기는 카카오 로컬로 대체했습니다.

## 티스토리

키워드 기반 글 갈래입니다 — 시드 풀 → 연관 키워드 조회 → 매일 초안 → 글 목록. 채널
컬럼(`posts.channel`)은 남아 있지만 값은 늘 `tistory` 입니다. 안 가본 가게 후기는 지어낼
수 없어서, 네이버는 사진에서 출발하는 **네이버 방문 후기** 갈래가 따로 맡습니다.

주제는 **n잡러·프리랜서의 돈 관리**(세금·신고 / 보험·연금 / 지원금·수당) 하나로 묶여
있습니다 — 매년 수치가 바뀌어 수요가 계속 있고, 정부·세무사 사이트보다 개인 블로그가
1차 정리로 인용될 여지가 있어서입니다. 왜 하나로 좁혔는지는 18장에 있습니다.

시드는 코드 상수가 아니라 설정 화면 **"시드 키워드 — 티스토리"**에서 편집합니다(비우면
`src/lib/seeds.ts` 의 기본값). 왜 코드 상수를 버렸는지도 18장에 있습니다.

1. **키워드 탐색** — 시드로 조회 → 연관 키워드 표
2. 후보를 체크하고 **경쟁 분석** → 상위권을 누가 잡고 있는지 확인
3. 마음에 드는 키워드의 **작성** → 메인 키워드로 넘어감
4. **글 작성** — `서브 키워드 제안` 으로 조합 후보 5개를 받고 하나 선택
5. **초안 생성** — 제목(메인+서브 포함), 본문, 태그, 메타 설명, FAQ 생성 + 자동 저장
6. **복사** — 티스토리는 HTML 복사
7. **티스토리** 화면 — 쓴 글을 목록으로 보고, 발행 여부를 수동 체크로 관리

### 키워드 모으기 (2주간)

지금은 글을 쓰지 않고, 시드 풀 전체를 매일 훑어 `keyword_pool` 에 쌓기만 합니다 — 조회
한 번은 그날의 스냅샷만 남아 "며칠째 꾸준히 나오는 키워드인지"를 알 수 없어서입니다.
쌓인 걸 보고 다음 시드를 정합니다. 스케줄은 아래 **자동화**를 보세요.

첫 수집(티스토리 시드 12개)에서 키워드 365개가 모였고, 그중 긴 키워드(질문형에 가까운
것)가 108개였습니다. 광고 흡수율 0%인 "계산기" 검색어 무리(프리랜서3.3%계산기,
사업소득세계산기, 퇴직소득세계산기 등)가 벌써 보입니다 — 자세한 내용은
[DEVLOG.md](DEVLOG.md) 18장을 보세요.

### 키워드 표 읽는 법

| 열 | 출처 | 의미 |
|---|---|---|
| 월간 검색 | 검색광고 키워드도구 | 최근 한 달 검색수(PC+모바일). `9`는 네이버가 `< 10`으로 가린 값 |
| 광고 단가 | 검색광고 입찰가 추정 | 1위 노출 예상 입찰가(모바일). **애드센스 단가의 대리 지표** |
| 수익 잠재력 | 계산값 | 검색수 × 단가 ÷ 1000. 트래픽과 단가를 묶은 비교 지수(금액 아님) |
| 모바일 | 계산값 | 모바일 검색 비중. **높을수록 블로그 유입에 유리** |
| 광고 흡수 | 계산값 | 월평균 광고 클릭수 ÷ 월간 검색수. **낮을수록 자연 결과로 갈 여지가 크다** |
| 광고 | 검색광고 키워드도구 | 경쟁정도(높음/중간/낮음)와 월평균 노출 광고수(0~15) |
| 최신글 | 검색결과 분석 | 상위 노출 글 중 최근 30일 내 비율. **높으면 계속 갈아치워지는 레드오션** |
| 인플루언서 | 검색결과 분석 | 상위 노출 블로그 중 인플루언서 비율. 높으면 일반 블로그가 밀림 |
| 진입 난이도 | 계산값 | 위 둘을 절반씩 섞은 0~100 |
| 문서수 · 경쟁률 · 추세 | 검색 API · 데이터랩 | *현재 발급 불가라 비어 있음* |

전부 공식 지표가 아니라 경험칙입니다. 절대값보다 같은 표 안에서의 상대 비교로 쓰세요.

### 뭘 보고 고르나

**애드센스는 2024년 3월부터 클릭이 아니라 노출(CPM)로 지급됩니다.** 수익은 대략
`페이지뷰 × 페이지 RPM`이고, RPM은 광고주가 그 주제에 얼마를 쓰는지로 정해집니다 —
국내 블로거 집계로 생활 주제는 1,000~2,500원, 금융·세금 주제는 10,000~30,000원 선입니다
(공식 수치가 아니라 추정치입니다). 세금·돈 주제를 계속 미는 이유이고, 예전 글 85편이
0원이었던 것도 주제 탓이 아니라 발행이 0편이라 페이지뷰 자체가 0이었기 때문입니다.

**새 블로그일 때.** 검색량 1위 키워드는 이미 세무사·보험사·정부 사이트나 오래된 블로그가
잡고 있어 새 글이 끼어들 자리가 없습니다. 이길 수 있는 자리는 따로 있습니다.

- **최소 검색 300** — 1,000 이상만 보면 레드오션만 남습니다. 티스토리 유입이 0이었던
  이유 중 하나입니다(18장)
- **광고 흡수율 2% 미만이면서 단가 2,000원 이상** — "흡수율 낮은 순"만 보면 구멍이
  있었습니다. 애드센스는 클릭이 아니라 노출로 버는데, 흡수율이 낮다는 건 "광고가 상단을
  안 가져간다"는 뜻이지 "그 주제에 광고주가 있다"는 뜻이 아닙니다. "실수령액계산기"는
  월 검색 88,500·단가 100원 — 사람은 오지만 광고주가 거의 없어 RPM이 바닥입니다. 두
  조건을 같이 걸어야 사람도 오고 단가도 붙는 자리가 남습니다
- **검색량 × 단가(수익 잠재력) 순** — 남은 후보 안에서 트래픽과 단가를 같이 봅니다
- **한 단어짜리는 뒤로** — 짧은 키워드는 이미 누군가 잡고 있을 확률이 높고 검색 의도도
  흐릿합니다. 긴 키워드(질문형)일수록 경쟁이 적고 검색 의도가 뚜렷해 글이 쓰기 쉽습니다

여기에 **모바일 비중**이 높으면 더 좋습니다.

정렬은 **잘라내기 전 전체 후보**에 적용되므로 검색량 상위에 없는 키워드도 발굴됩니다.
(단 **경쟁률·문서수 정렬**은 문서수를 조회한 뒤에야 알 수 있어 상위 N개 안에서만 정렬됩니다.)

**티스토리는 네이버가 아니라 구글·다음에서 유입됩니다.** 네이버 기준 지표만 보고 고르면
채널의 실제 유입 경로와 어긋납니다.

- 시즌 키워드는 4~6주 전에 선점하세요 — 검색이 몰리고 나면 이미 늦습니다
- 계산기 같은 도구 글은 체류시간이 길고 다른 글이 링크로 인용하기 쉽습니다
- 청약 일정처럼 **자기만의 1차 소스**가 있으면 남이 베낄 수 없는 글이 됩니다
- 발행한 글은 쓰레드로 밀어 초기 유입을 만듭니다
- GA4·서치콘솔로 실제로 뭐가 들어오는지 재보고 다음 시드를 고릅니다

### 경쟁 분석

광고 흡수율로 후보를 좁혔으면 최대 20개를 체크하고 **경쟁 분석**을 누르세요. 두 지표는 서로
다른 것을 봅니다 — **광고 흡수율은 수요의 성격**(정보성이냐 구매성이냐), **진입 난이도는 지금
공급 상태**(누가 상위를 잡고 있나)입니다.

```
8월제주날씨    광고 흡수 0%   진입 난이도 57   최신글 90%, 중앙연령 14일
제주도박물관   광고 흡수 0.1%  진입 난이도 17   최신글 20%, 중앙연령 48일
```

둘 다 정보성이지만, 앞쪽은 8월이라 새 글이 쏟아지는 중이고 뒤쪽은 오래된 글이 상위에 남아
비집고 들어갈 자리가 있습니다.

이 기능은 공식 API 가 아니라 **공개 검색 페이지를 읽습니다.** 버튼을 눌렀을 때만, 동시 2개 ·
요청 간 0.4초로 돕니다(20개에 약 25초). 네이버가 마크업을 바꾸면 깨지고, 그때는 그렇게
알려줍니다. 상시 크롤러가 아니므로 이 정도 빈도를 유지하세요.

### 붙여넣기 요령

| 대상 | 버튼 | 방법 |
|---|---|---|
| 네이버 블로그 | `네이버 본문 (서식 유지)` | 스마트에디터 ONE 본문에 그대로 ⌘V. 소제목·굵게·목록이 살아납니다 |
| 티스토리 | `티스토리 본문 (HTML)` | 에디터를 **HTML 모드**로 전환한 뒤 ⌘V |

제목·태그·JSON-LD 는 별도 버튼으로 복사합니다.

## 네이버 방문 후기

키워드가 아니라 **사진에서 출발**하는 갈래입니다. 방향이 반대라 글 작성과 섞지 않습니다.
발행 대상이 네이버 블로그라 갈래 이름에도 네이버를 붙였습니다.

1. **올리기** — 외관·메뉴판·음식 사진과 장소명, 방문일을 넣습니다
2. **분석** — 사진에서 메뉴·가격·관찰 사실을 읽고(OpenAI GPT, 기본 `gpt-5.5`), 카카오
   로컬로 정확한 상호·주소를 동시에 붙입니다
3. **30초 인터뷰** — 누구랑, 뭐가 기억에 남는지, 또 갈 건지. 객관식 셋 + 자유 입력 하나
4. **초안 생성** — 사진에서 나온 사실 + 인터뷰의 감상으로 본문을 씁니다(OpenAI GPT).
   티스토리 본문은 계속 Gemini 입니다 — 사진(메뉴판 OCR·음식 식별)이 핵심인 갈래라
   시각 인식이 강한 모델에 맡겼습니다

사진에도, 카카오 조회에도, 인터뷰에도 없는 것은 쓰지 않습니다 — 안 시킨 메뉴의 맛이나
웨이팅 시간처럼 AI 가 반사적으로 지어내는 것들입니다. 메뉴판·영수증 사진이 없으면 가격을
아예 언급하지 않습니다. 남의 후기 문장도 가져오지 않습니다(요약해 넣으면 네이버 유사문서
필터에 걸려 글이 노출되지 않습니다).

**사진 원본은 저장하지 않습니다.** 분석 결과만 남고, 발행은 사용자가 휴대폰에서 직접 하므로
서버가 원본을 들고 있을 이유가 없습니다.

## 개발 로그

깃 커밋을 매일 모아두고, 주 1회 velog 글 초안을 만들고, 승인한 것만 올리는 갈래입니다.
원래 [y10b/devlog](https://github.com/y10b/devlog) 라는 별도 레포였습니다 — 노션 DB 세 개를
저장소로 쓰고 깃액션 네 개가 각자 돌았습니다. 승인 화면이 노션에 있으면 검토가 두 곳으로
갈리므로 이 백오피스로 합쳤습니다. devlog 레포는 이 뒤 삭제할 예정입니다.

| 단계 | 언제(KST) | 하는 일 |
|---|---|---|
| 수집 | 매일 21:00 | 그날 커밋을 레포별로 모아 `dev_logs` 에 쌓습니다(회사 레포 제외) |
| 초안 | 매일 22:30 | 최근 7일에서 글감 하나를 골라 `velog_posts` 에 초안을 만듭니다 (점수 2 미만이면 비움) |
| 발행 | 매일 07:00 | 상태가 **발행 승인**인 것만 velog 에 올립니다 |
| 역동기화 | 매일 22:00 | velog 에 올라간 글·반응(좋아요·댓글)을 되돌려 채웁니다 |

저장소는 Supabase 입니다 — `dev_logs`(하루·레포 단위 커밋 묶음, 글의 재료)와
`velog_posts`(글, 자동 초안과 역동기화 이력이 한 표에 있음). 화면은 `/devlog` — 검토·승인,
직접 실행 버튼, 최근 로그를 봅니다.

실행 진입점은 하나입니다. `src/lib/devlog.ts` 의 `runTask` 를 깃액션(`scripts/devlog.mjs`) ·
화면 버튼(`/api/devlog/run`) · 크론 라우트(`/api/cron/devlog`)가 똑같이 부릅니다. 워크플로도
하나(`.github/workflows/devlog.yml`)입니다 — 크론 4개를 `github.event.schedule` 문자열로
분기하고, **제휴 후보 워크플로처럼 러너 안에서 스크립트를 직접 돌립니다.** 배포본을 거치지
않으므로 머지·배포 전에도 이 파일이 있는 브랜치에서 바로 돕니다. 레포 시크릿은 `SUPABASE_URL`,
`SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY` 면 됩니다(GitHub 토큰·velog 쿠키는 설정 표에서
읽습니다). 공개 레포라 액션 로그에는 개수만 남깁니다.

자격증명은 설정 화면 **"GitHub · velog"** 카드에 있습니다 — GitHub PAT(classic, `repo`
스코프), GitHub 사용자, velog 사용자(GitHub 과 다를 때만), velog access_token(쿠키), 수집하지 않을 소유자
목록(기본 `bambitcorporation` 은 항상 포함). 자세한 발급 방법은 위 **자격증명 → 선택 — 개발 로그**를 보세요.

**노션에 있던 과거 초안은 옮기지 않았습니다.** 발행 이력은 역동기화가 velog 에서 되돌려
채우고, 옮길 때 작성 중이던 초안은 손으로 옮겨야 합니다.

## 유입 데이터

`성과` 화면에서 GA4 조회수·애드센스 수익·서치콘솔 검색 노출을 글 단위로 붙여 봅니다. GA4 는
"들어온 뒤"만 보여주고, 어떤 검색어로 몇 번 노출됐고 몇 위인지는 서치콘솔에만 있습니다 —
다음 글감은 결국 서치콘솔이 가리킵니다.

### 매일 다시 쌓는다

GA4 와 서치콘솔은 서비스 계정 하나로 묶습니다(GA4 는 편집자, 서치콘솔은 전체 권한 — 위
**자격증명** 참고). 매일 09:30 KST 깃액션(`insights.yml`)이 최근 7일을 다시 조회해
`search_daily`·`traffic_daily`·`event_daily` 를 덮어씁니다. 서치콘솔 데이터는 확정까지
2~3일 걸리므로, 최근 며칠치를 매일 다시 받아 잠정치를 확정치로 갈아끼웁니다.

성과 화면에서 보는 것:

- **검색 노출·클릭·세션** — 서치콘솔 노출·클릭과 GA4 세션을 나란히 봅니다
- **기회 검색어** — 노출은 되는데 5~30위인 검색어. 다음 글감 후보입니다
- **유입 경로** — 어디서 왔는지(네이버는 서치어드바이저에 API 가 없어 GA4 의 소스 값으로만
  잡힙니다)
- **페이지별** — 글 단위 조회수·체류시간
- **이벤트** — 계산기 글에서 계산을 누르면 쏘는 `calculator_use`(3.3% 환급 계산기·
  세금계산기, `calc_type` 으로 구분) 등을 봅니다

### 다음 글감을 자동으로 고른다

1. **글감 큐**(설정 `post_queue`)에 있으면 그걸 먼저 씁니다
2. 큐가 비면 **기회 검색어**(위) 중 상위를 씁니다
3. 그것도 없으면 **키워드 풀**(새 기준 — 위 **뭘 보고 고르나** 참고)로 돌아갑니다

초기 큐 7개는 프리랜서 종합소득세·3.3% 환급 계산기·지역가입자 건강보험료·퇴직금중간정산·
종합소득세신고·세금계산기·양도세기본세율입니다 — 다음 모바일 통합검색으로 확인했을 때 세무
서비스·정보 모음 사이트·오래된 커뮤니티 글이 상위라 경쟁이 약한 키워드들입니다. 키워드 수집
시드에는 상위 기회 검색어 5개를 더해서, 네이버 검색광고 지표만이 아니라 실제 유입 쪽으로도
풀을 넓힙니다.

**발행은 여전히 사람이 합니다.** 티스토리 Open API 가 사실상 종료됐고, 브라우저 자동화는
로그인 계정(카카오)이 걸려 있어 위험합니다 — 자동 발행을 만들지 않는 이유는 아래 **알아둘
점**과 같습니다.

체류시간이 30초 미만이면 제목과 본문이 안 맞아 바로 나간 것입니다 — 검색 의도를 다시 보세요.

## 자동화

네 워크플로가 깃액션 러너 안에서 직접 돕니다. 예전에는 배포본의 `/api/cron/*` 를 curl 로
불렀지만, 그러면 머지·배포·`CRON_SECRET` 이 먼저 있어야 첫 실행이 됐습니다. 지금은 DB ·
API 시크릿만 레포에 등록하면 이 파일이 있는 브랜치에서 바로 돕니다(제휴 후보·개발 로그와
같은 방식). 크론 라우트(`/api/cron/daily-post`, `/api/cron/devlog`)는 남아 있지만,
워크플로는 더 이상 이 라우트를 부르지 않습니다.

| 워크플로 | 언제(KST) | 하는 일 |
|---|---|---|
| `keywords.yml` (키워드 모으기) | 매일 06:00 | 티스토리 시드 풀 전체로 연관 키워드를 조회해 `keyword_pool` 에 upsert(`src/lib/keywordPool.ts`) |
| `daily-post.yml` (매일 블로그 초안) | 매일 06:30 | 티스토리 초안 **하루 1편** 생성. 당분간 꺼둠 |
| `devlog.yml` (개발 로그) | 21:00 / 22:00 / 22:30 / 07:00 | 커밋 수집 · 역동기화 · velog 초안 · 발행 — 위 **개발 로그** 절 참고 |
| `insights.yml` (유입 데이터 수집) | 매일 09:30 | GA4·서치콘솔 최근 7일을 다시 조회해 `search_daily`·`traffic_daily`·`event_daily` 에 덮어쓰기 — 위 **유입 데이터** 절 참고 |

`daily-post.yml` 이 다시 켜지면 편당 Gemini 키 하나씩 써서 키 수만큼 여러 편을 만들던
예전 방식은 없앱니다 — 정확히 하루 1편입니다.

SERP 경쟁 분석은 자동 생성에서 하지 않습니다 — 네이버 검색 페이지를 읽는 것이라 실패해도
글은 나와야 하고, 자동 실행에서는 사람이 결과를 보고 판단할 수도 없습니다. 검색광고
데이터만으로 고릅니다.

### 꺼둔 것

| 워크플로 | 상태 | 이유 |
|---|---|---|
| `daily-post.yml` (매일 블로그 초안) | 당분간 꺼둠 | 2주 동안 키워드만 모아 주제를 정합니다 — 그동안은 안 쓰는 편이 레드오션 글을 쓰는 것보다 낫습니다(18장) |
| `affiliate-picks.yml` (쓰레드 제휴 후보) | 꺼둠 | 방향이 바뀌었습니다 — 나중에 인스타그램과 같이 다시 설계합니다. 코드와 화면(`/threads`)은 남겨 둡니다 |

## 화면

아이폰에서 쓰는 걸 전제로 합니다 — 출근길에 승인하고 글을 복사하는 용도라, 화면 폭에 따라
같은 데이터를 다른 틀에 담습니다.

- **모바일** — 아이폰 "설정" 앱과 같은 인셋 그룹 리스트. 라이트/다크는 시스템 설정을 따라
  자동으로 바뀝니다. 상단 내비게이션 바와 뒤로가기로 화면을 오갑니다.
- **데스크톱·태블릿** — iPad 설정 앱의 스플릿 뷰. 왼쪽에 메뉴 목록, 오른쪽에 선택한 화면의
  상세가 함께 뜹니다.

라우트가 바뀌었습니다. `/` 는 **홈**(오늘 할 일 개수, 모바일에서는 메뉴 루트를 겸함)이고,
키워드 탐색은 `/keywords` 로 옮겼습니다.

메뉴는 세 묶음입니다.

| 묶음 | 항목 |
|---|---|
| 블로그 | 키워드 탐색 · 글 작성 · 티스토리 · 네이버 방문 후기 |
| 채널 | 개발 로그 · 쓰레드 |
| — | 성과 · 설정 |

홈의 할 일 줄도 같은 이름을 씁니다 — "티스토리 초안 (안 올림)", "네이버 방문 후기
(진행 중)".

### 표 대신 리스트

아이폰 폭에서 열이 많은 표는 제목이 세로로 쪼개져 읽을 수 없습니다. **티스토리** 화면은
표를 버리고 iOS 리스트 행(제목 + 발행 상태)으로 바꿨습니다. 키워드 탐색·경쟁 분석처럼
열끼리 비교가 필요한 표는 리스트로 바꾸지 않고 최소 폭을 두어 가로 스크롤로 봅니다.

## 배포

Vercel 에 올릴 수 있습니다. 영상 렌더가 빠지면서 로컬 워커도 함께 없어졌습니다 — 배포본
하나로 끝입니다.

배포 시 `BACKOFFICE_PASSWORD` 를 **반드시** 넣으세요. 비우면 인증이 꺼지고, URL 을 아는
누구나 API 키와 수익 데이터를 봅니다. `SESSION_SECRET` 과 `APP_ORIGIN` 도 함께 설정하세요.

GitHub Actions 워크플로 넷(`keywords`·`daily-post`·개발 로그·`insights`)은 배포본을 거치지
않고 러너 안에서 소스를 체크아웃해 직접 돕니다 — 레포 시크릿에 `SUPABASE_URL`·
`SUPABASE_SERVICE_ROLE_KEY`·`NAVER_SEARCHAD_*`·`GEMINI_API_KEY` 를 등록하면 배포·머지와
무관하게 돕니다. 자세한 이유는 위 **개발 로그** 절과 **자동화** 절을 보세요. 크론 라우트는
남아 있지만 워크플로는 더 이상 부르지 않습니다.

## 알아둘 점

- **자동 발행은 없습니다.** 네이버 글쓰기 API 는 폐지됐고 티스토리 Open API 도 사실상
  종료돼서, 자동 발행은 브라우저 자동화 외에 방법이 없습니다. 복사용 결과물까지만 만듭니다.
- **velog 발행은 공식 API 가 아니라 로그인 쿠키입니다.** 쿠키가 만료되면 조용히 멈추는 대신
  글에 오류를 남기고 크론을 실패로 끝냅니다 — 방치하면 승인만 쌓이고 아무것도 안 올라간
  상태를 눈치채기 어렵습니다.
- **생성된 본문의 수치·날짜·가격은 검증하세요.** 검색 그라운딩으로 억제하고는 있지만
  완전하지 않습니다. 네이버 방문 후기는 메뉴판·영수증 사진이 없으면 가격 자체를 쓰지 않습니다.
- 크리에이터 어드바이저는 연동하지 않습니다. 내부 API 가 HMAC 서명으로 막혀 있고 우회하지
  않기로 했습니다. 경위는 [DEVLOG.md](DEVLOG.md) 5장에 있습니다.
